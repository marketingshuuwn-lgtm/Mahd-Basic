# تقرير التحقق من العضويات والمصادقة والصلاحيات الفعلية

## الحكم التنفيذي

مَهَد الحالية **لا تحتوي على عضويات أو مصادقة أو صلاحيات فعلية**. الموجود هو قاموس أدوار ومصفوفة صلاحيات محلية ومسار Pilot مقيد بهوية مالك ثابتة. هذه الأجزاء مفيدة لتثبيت لغة المنتج وحدود الاختبار، لكنها لا تحمي بيانات فريق ولا تحقق هوية مستخدم.

السبب البنيوي واضح: المشروع الحالي تطبيق Vite/React يعمل في الواجهة، ولا توجد طبقة Backend أو جلسات خادم أو قاعدة بيانات مستخدمين أو API للمصادقة. لذلك لا يمكن اعتبار أي قرار صلاحية داخل الواجهة صلاحية أمنية فعلية.

## فحص المصادقة

| العنصر | ما وجدته فعليًا | الحكم |
|---|---|---|
| تسجيل الدخول | لا توجد صفحة أو دالة أو مسار login | غير موجود |
| تسجيل الخروج | لا توجد جلسة أو عملية logout | غير موجود |
| الجلسة | لا توجد cookies أو JWT أو session server | غير موجود |
| المستخدم الحالي | لا يوجد كيان user أو مصدر هوية | غير موجود |
| Backend | `package.json` يحتوي React/Vite فقط ولا توجد خوادم تطبيق | غير موجود |
| قاعدة بيانات هوية | لا توجد جداول أو schema أو migrations | غير موجود |
| OAuth | لا توجد مسارات أو إعدادات OAuth داخل المشروع | غير موجود |

حفظ بعض الحالة في `localStorage`، مثل إعدادات ومساحات العمل واتصال Trello، لا يمثل مصادقة. يستطيع أي مستخدم للمتصفح قراءة هذه القيم وتعديلها، ولا تثبت هوية أو ملكية.

## فحص العضويات ومساحات العمل

يوجد hook باسم `useWorkspaces` يدير مساحات عمل محلية ويخزنها في `localStorage`. هذه المساحات ليست workspaces مشتركة على الخادم، ولا ترتبط بمستخدم أو عضوية أو دعوة أو مالك أو سياسة عزل.

| المفهوم المطلوب | الحالة الحالية |
|---|---|
| مساحة عمل مشتركة | غير موجودة؛ الموجود سياق محلي للمتصفح |
| المستخدم داخل المساحة | غير موجود |
| عضوية المستخدم | غير موجودة |
| دعوة عضو | غير موجودة |
| إزالة عضو أو تعطيل عضويته | غير موجودة |
| حالة العضوية `invited/active/suspended` | غير موجودة |
| مالك مساحة العمل الخادمي | غير موجود؛ يوجد فقط `owner-local-pilot` ثابت |
| عزل بيانات مساحة عن أخرى | غير مثبت؛ التخزين المحلي مرتبط بالمتصفح لا بحدود وصول خادمية |

## فحص الأدوار

يوجد قاموس `mahdRoles.js` يثبت الأدوار التشغيلية التسعة: المالك، مدير الحساب، كاتب المحتوى، المصمم، المصور، مسؤول الميديا، منسق المشاريع، مدير المشاريع، ومنفذ الحملات. هذا **تعريف منتجي** وليس عضوية أو إسنادًا إلى مستخدم حقيقي.

## فحص الصلاحيات

مصفوفة `mahdPermissionMatrix.js` تغطي ثلاثة إجراءات لصندوق المزامنة: اعتماد العملية، تنفيذ العملية المعتمدة، وحل التعارض. المالك فقط حالته `active`، بينما الأدوار الثمانية الأخرى `not_decided`.

`mahdPermissions.js` يستخدم هوية ثابتة باسم `مالك مساحة مَهَد` ومعرّف `owner-local-pilot`. هذا مفيد لاختبار الحارس، لكنه لا يقرأ هوية من جلسة ولا يتحقق من العضوية أو مساحة العمل أو صلاحية خادمية.

| سؤال الصلاحية الفعلية | النتيجة الحالية |
|---|---|
| هل يمكن معرفة من ينفذ الطلب؟ | لا، توجد هوية Pilot ثابتة فقط |
| هل يتحقق النظام من عضوية المستخدم؟ | لا توجد عضوية أصلًا |
| هل يتحقق من workspaceId؟ | لا يوجد سياق خادمي مفروض |
| هل تمنع الصلاحية الطلب من الخادم؟ | لا يوجد خادم |
| هل يمكن للمستخدم تجاوزها بتعديل الواجهة؟ | نعم، لأنها منطق واجهة/وحدات JavaScript محلية |
| هل الأدوار الثمانية الأخرى مفعلة؟ | لا، حالتها غير محسومة عمدًا |

## فحص عزل البيانات

بيانات مَهَد الأساسية تحفظ عبر مستودع محلي قابل للاستبدال، لكن التنفيذ الحالي `localStorage`. هذا يحسن قابلية تبديل التخزين، ولا يوفر عزلًا أو ملكية أو صلاحيات. كما توجد استخدامات أخرى مستقلة لـ`localStorage` في إعدادات الواجهة ومساحات العمل واتصال Trello.

## الاختبارات الحالية

تم تشغيل **33 اختبارًا بنجاح، دون فشل**، وتشمل اختبارات نموذج الأدوار، مصفوفة الصلاحيات، حارس Pilot، المستودع، الاستمرارية، المزامنة والتعارضات. كما نجح `npm run build`.

هذه الاختبارات تثبت السلوك المحلي المقصود، ولا تثبت مصادقة حقيقية أو حماية Backend أو عزل multi-tenant؛ فلا توجد هذه الطبقات أصلًا لاختبارها.

## ما يلزم لبناء فعلي

لبناء الخيار أ، يلزم أولًا اعتماد Backend وقاعدة بيانات مشتركة دون افتراض Supabase. النموذج الأدنى يحتاج جداول أو كيانات للمستخدمين، ومساحات العمل، والعضويات، والدعوات، والأدوار، والصلاحيات، وربط كيانات مَهَد بمساحة العمل.

كما يلزم مسار جلسة خادمية أو مزود OAuth، وإجراءات محمية تتحقق من هوية المستخدم ثم عضويته ثم صلاحية الإجراء ثم ملكية السجل لمساحة العمل. يجب أن تكون الواجهة مستهلكًا للصلاحيات وليست مصدرها الوحيد.

## القرار

بوابة **تعريف الأدوار والصلاحيات التجريبية** ناجحة. بوابة **العضويات والمصادقة والصلاحيات الفعلية** غير موجودة بعد. لا ينبغي توسيع صلاحيات Pilot أو إعلان جاهزية الفريق قبل بناء Backend مشترك أو اعتماد خيار ب بوضوح كحل محاكاة مؤقت.
