# أساس Backend وقاعدة البيانات لمَهَد

## الحالة

تم إنشاء أساس Backend مستقل عن مسار Supabase الجديد. الخادم الحالي يستخدم Node HTTP وقاعدة SQLite مشتركة على الخادم، مع واجهة تخزين قابلة للترحيل لاحقًا. هذا اختيار مرحلي مناسب للـPilot منخفض التكلفة، وليس إعلانًا أن SQLite هو المحرك النهائي للمنصة على المدى الطويل.

## ما تم بناؤه

| الجزء | الحالة |
|---|---|
| خادم Backend | `server/index.mjs`، مع `/health` ومسارات قراءة أولية |
| قاعدة البيانات | `server/db.mjs`، مخطط SQLite مشترك |
| Workspace | جدول مستقل، وقراءة الكيانات تتطلب `x-workspace-id` |
| المستخدمون والعضويات | جداول أولية فقط؛ المصادقة لم تُبنَ بعد |
| العملاء والمشاريع والمهام | جداول بعلاقات وقيود Foreign Key |
| المخرجات والعمل الداخلي | جداول مستقلة مرتبطة بمساحة العمل |
| Pilot والمزامنة | جداول أولية لسجل التشغيل والعمليات |
| اختبارات Backend | عزل Workspace والعلاقات ومخطط القاعدة |
| أوامر التشغيل | `npm run backend` و`npm run test:backend` |

## قرار SQLite المرحلي

تم اختيار SQLite في هذه المرحلة لأن الهدف هو بناء Backend مشترك بسيط وقابل للتشغيل على خادم واحد دون إدخال خدمة مُدارة أو Supabase. قاعدة SQLite هنا ليست `localStorage`؛ هي ملف قاعدة على الخادم، ويمكن أن يراه أكثر من جهاز عبر API واحد.

قبل الإنتاج الموسع، يجب تقييم الانتقال إلى PostgreSQL أو MySQL/TiDB بحسب بيئة الاستضافة ومتطلبات التزامن والنسخ الاحتياطي. لا يجوز اعتبار SQLite حلًا نهائيًا قبل اختبار الكتابات المتزامنة، النسخ الاحتياطي، الاستعادة، ومراقبة القاعدة.

## العزل الحالي وحدوده

المسارات الحالية تتطلب `x-workspace-id` وتستعلم بالـ`workspace_id`. هذا يثبت أساس عزل البيانات، لكنه ليس حماية مستخدم فعلية؛ لأن قيمة الرأس يمكن للمستخدم تغييرها قبل بناء المصادقة والعضوية. في المرحلة التالية يجب استبدال الرأس غير الموثوق بـWorkspace مستخرج من جلسة مستخدم وعضوية خادمية.

## آثار Supabase القديمة

يحتوي المشروع القديم على `@supabase/supabase-js` وملفات `src/lib/supabaseClient.js` و`supabase/` مرتبطة بوظائف قديمة مثل جلسات Pomodoro والإشعارات. لم يستخدم Backend الجديد Supabase، ولم تُحذف الآثار القديمة في هذه المرحلة لتجنب كسر وظائف غير داخلة في نطاق الخادم الجديد. يجب إجراء جرد وترحيل منفصل قبل إزالة الاعتماد القديم.

## بوابة قبول المرحلة

تُعد هذه المرحلة ناجحة كـ**أساس Backend** لأن الخادم يعمل، ومخطط القاعدة يُنشأ، وقراءة Workspace مطلوبة، والعلاقات الأساسية محفوظة، والاختبارات والبناء ناجحان. لكنها لا تعني اكتمال العضويات أو المصادقة أو الصلاحيات؛ تلك هي المرحلة التالية.
