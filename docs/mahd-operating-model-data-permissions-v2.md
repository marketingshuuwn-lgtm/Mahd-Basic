# النموذج التشغيلي للبيانات والصلاحيات — مسودة قرار

## نطاق الوثيقة

هذه الوثيقة لا تنشئ قاعدة بيانات ولا تطبق صلاحيات داخل التطبيق. هدفها تثبيت النموذج الذي ستُبنى عليه المراحل القادمة، مع الفصل بين الحقائق التي أكدها المشروع والاقتراحات التي تحتاج اعتمادًا.

## حقائق معتمدة

مَهَد منتج يومي لوكالة تسويق من ثمانية موظفين، ويضم الأدوار التشغيلية التالية: المالك، مدير الحساب، كاتب المحتوى، المصمم، المصور، مسؤول الميديا، منسق المشاريع، مدير المشاريع، ومنفذ الحملات. في Pilot الحالي، المالك ومدير المشاريع شخص واحد.

الكيانات التشغيلية الأساسية هي العميل، المشروع، المهمة، المخرج، الصفحة/المعرفة، القالب، والعمل الداخلي. ثبات ومزاد بركة وسنام وعلامة تسويق عملاء، بينما علامة الأم مساحة عمل داخلية إدارية وتنظيمية وليست عميلًا.

## النموذج المقترح

يقترح النموذج أن يكون لكل مهمة علاقة صريحة بعميل ومشروع عند كونها عملًا خارجيًا، أو بمسار العمل الداخلي عند كونها إدارية. ولا تُنشأ علاقة مشروع ضمنية من Label أو اسم قائمة Trello.

| الكيان | الحقول المنطقية الأولية | العلاقات |
|---|---|---|
| العميل | الاسم، الحالة، جهات الاتصال، السياق، `externalRefs` | يملك مشاريع متعددة ومخرجات متعددة. |
| المشروع | الاسم، النوع، النطاق، الحالة، العميل، قائد المشروع، `externalRefs` | يتبع عميلًا ويضم مهامًا وصفحات ومخرجات. |
| المهمة | العنوان، الوصف، الحالة، المالك، الموعد، الأولوية، المشروع أو المسار الداخلي، `externalRefs` | تنتمي إلى مشروع أو عمل داخلي، ويمكن أن ترتبط بمخرج وصفحة. |
| المخرج | الاسم، النوع، الحالة، رابط الملف/الصفحة، المراجع | يتبع مشروعًا ومهمة أو أكثر. |
| الصفحة | العنوان، النوع، المحتوى، الحالة، المالك، المراجع | ترتبط بعميل أو مشروع أو معرفة داخلية. |
| القالب | الاسم، نوع سير العمل، الخطوات، الإصدار | يُستخدم لإنشاء مشروع/مهام، ولا يساوي مشروعًا حقيقيًا. |
| المزامنة | الكيان الداخلي، نوع العملية، المصدر، الحالة، آخر قراءة، آخر كتابة، الخطأ | تربط مَهَد بـ Trello دون كشف تفاصيلها في المسار اليومي. |

## الصلاحيات المقترحة

تُبنى الصلاحيات على الدور والسياق معًا؛ فلا يكفي أن يكون المستخدم عضوًا في الفريق للوصول إلى كل العملاء والمشاريع. هذا نموذج أولي قابل للمراجعة وليس قرارًا نهائيًا.

| الدور | ما يحتاجه يوميًا | صلاحيات مقترحة تحتاج اعتمادًا |
|---|---|---|
| المالك/مدير المشاريع | رؤية كل الوكالة، اعتماد النطاقات، قرارات المزامنة، المخرجات | إدارة العملاء والمشاريع والقوالب، اعتماد الكتابة الخارجية، رؤية التعارضات. |
| مدير الحساب | سياق العملاء، المشاريع المسندة، المخرجات والتسليمات | إنشاء/تحديث سياق العميل، اقتراح مشروع، إنشاء مهام، طلب مزامنة؛ لا يعتمد وحده تغييرات حساسة. |
| منسق المشاريع | حالة المشاريع، توزيع العمل، المواعيد | إنشاء مهام وتحديث حالات ضمن المشاريع المسندة؛ لا يغير بيانات العميل الأساسية. |
| كاتب المحتوى/المصمم/المصور/مسؤول الميديا/منفذ الحملات | مهامي، صفحات ومخرجات المشاريع المسندة | تحديث المهام والمخرجات المسندة؛ لا ينشئ عميلًا ولا يعتمد ربطًا خارجيًا. |

## مبدأ الاعتماد

الإنشاء داخل مَهَد لا يعني الكتابة الفورية إلى Trello. كل عملية خارجية لها سجل معاينة يوضح: الكيان الداخلي، العملية المقترحة، البطاقة أو Label أو القائمة المتأثرة، وما لن يتغير. بعد موافقة صاحب الصلاحية تُنفذ العملية، ثم تسجل النتيجة داخل مَهَد.

## قرارات مطلوبة قبل نموذج التخزين النهائي

| القرار | لماذا يغيّر البناء |
|---|---|
| هل يرى كل عضو كل العملاء أم العملاء المسندين فقط؟ | يحدد نموذج العضوية ومرشح الاستعلامات والصلاحيات. |
| هل المشروع المركب مثل سنام مشروع واحد بمسارين أم مشروع رئيسي بمشاريع فرعية؟ | يحدد العلاقة بين المشاريع والمهام والمخرجات. |
| هل إنشاء العميل في مَهَد ينشئ Label Trello تلقائيًا بعد الموافقة؟ | يحدد عملية الكتابة الخارجية ومعالجة تعارض Label موجود. |
| هل المهمة المنشأة في مَهَد تُكتب كبطاقة فور موافقة واحدة أم تحتاج اعتمادًا إضافيًا؟ | يحدد صندوق الموافقة وسلطة الأدوار. |
| ما الذي يحدث عند تعديل البطاقة من Trello بعد إنشائها من مَهَد؟ | يحدد سياسة المصدر الغالب والتعارضات. |
| ما مدة بقاء Trello طبقة خلفية؟ | يحدد مقدار الاستثمار في المزامنة مقابل التخزين المستقل. |
