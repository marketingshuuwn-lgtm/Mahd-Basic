# عقد Project Hub — نسخة Trello-only

## القرار

هذا العقد يصف **السلوك التشغيلي القديم القائم** في وضع Trello-only: يمثل كل Trello Board مشروعًا واحدًا في مَهَد. لا توجد قاعدة بيانات مَهَد مستقلة، ولا جدول Projects محلي مخفي؛ اسم المشروع ورابطه وقوائمه وبطاقاته كلها مملوكة لـ Trello.

> **قيد الجسر المعتمد لاحقًا:** في Board `3QDjP1P2` الخاص بالـ Pilot، تمثل Labels `THB - ثبات` و`BRK - مزاد بركة` العميلين «ثبات» و«مزاد بركة»، لا المشروعين. لذلك لا يصلح هذا العقد لتحديد مشروع Card داخل ذلك Board، ولا يجوز تعديل التطبيق ليعامل Label كـ Project Key من دون إشارة مشروع إضافية معتمدة.

## المصطلحات

| مَهَد | Trello | السلوك |
|---|---|---|
| مشروع في السلوك القديم | Board | اختيار مشروع يبدّل Board النشط للتطبيق |
| مرحلة تنفيذ | List | قائمة Board تحدد حالة المهمة وفق خريطة سير العمل |
| مهمة | Card | بطاقة Trello هي المهمة المعروضة في كل Views |
| Project Hub | قائمة Boards المتاحة | يعرض المشاريع ويربطها بالتطبيق، ولا ينشئ كيانًا موازيًا |

## ما ستقدمه النسخة

- Project Hub يعرض Boards المتاحة ويحدد الـ Board النشط.
- كل Views للمهام — Table وBoard وTimeline وCalendar وGantt — تستخدم البطاقات من Board النشط نفسه.
- تظهر هوية المشروع النشط بوضوح في مساحة العمل والعروض.
- يمكن الانتقال إلى Board آخر من Project Hub، ومن ثم تتغير مجموعة المهام تلقائيًا.
- تبقى حالات مَهَد مرتبطة بقوائم Trello كما في `trelloWorkflow`.

## حدود الجسر المستهدف — غير منفذة بعد

| المصدر | المفتاح المرحلي الصحيح | ما لا يجوز استنتاجه |
|---|---|---|
| Board `3QDjP1P2` | مصدر مجموعة Cards التجريبية | أن Board نفسه يمثل مشروعًا أو عميلًا. |
| Label `THB - ثبات` | مفتاح عميل «ثبات» | أن Label يمثل مشروعًا. |
| Label `BRK - مزاد بركة` | مفتاح عميل «مزاد بركة» | أن Label يمثل مشروعًا. |
| Card | مهمة مرتبطة بعميل معروف | اسم أو هوية المشروع من دون حقل/Label/Custom Field أو خريطة إضافية معتمدة. |

يتطلب جسر الوكالة مستقبلاً معاينة قراءة فقط تعرض: العميل المستنتج من Label، وإشارة المشروع المستخدمة أو الغائبة، وأي Cards لا يمكن مطابقتها. لا تُنفذ أي كتابة أو نقل Card قبل الموافقة الصريحة. يبقى السلوك القديم أعلاه كما هو حتى ينفذ هذا الجسر ويختبر على بيانات Pilot.

## الحدود المتعمدة

- لا توجد مشاريع فرعية أو عميل أو ميزانية أو أعضاء أو نسبة إنجاز مخزنة في مَهَد.
- لا توجد علاقات Tasks/Projects خارج ما توفره Trello، ولا صلاحيات فريق مستقلة عن صلاحيات Trello.
- لا يتم حساب مؤشرات كل Boards تلقائيًا، لتفادي طلبات API جماعية وحدود المعدل؛ Project Hub يعرض معلومات Board المتاحة، بينما إحصاءات التنفيذ تخص المشروع المختار.
- إنشاء أو أرشفة مشروع يعني إنشاء أو إغلاق Board في Trello؛ هذا ليس ضمن هذه الشريحة حتى لا يحدث تغيير واسع غير مؤكد في بيانات المستخدم.
- أي انتقال لاحق إلى مخزن بيانات مستقل سيحتفظ بـ `trello_board_id` بوصفه مصدرًا خارجيًا للـ Board، ولا يعامله تلقائيًا كمعرّف مشروع. تحدد المعرّفات الخارجية للعميل والمشروع بعد اعتماد خريطة الجسر.

## معايير القبول

1. في السلوك القديم فقط، يستطيع المستخدم رؤية Boards التي يملك حق الوصول إليها بوصفها مشاريع.
2. يختار Board من Project Hub، فتظهر بطاقاته نفسها في كل Views من دون إعادة إدخال بيانات.
3. كل مهمة تعرض قائمة Trello وحالتها في العروض المدعومة.
4. لا يُنشأ Board أو Card أو يُنقل شيء في Trello بمجرد التنقل أو العرض.
5. تبقى عمليات كتابة Card الحالية محصورة في Board النشط.
