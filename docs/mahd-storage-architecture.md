# طبقة تخزين مَهَد القابلة للاستبدال

## القرار الحالي

تم فصل مستودع مَهَد عن تنفيذ التخزين. `createMahdRepository` يحتفظ بواجهة المجال نفسها، لكنه يقبل الآن `adapter` اختياريًا. إذا لم يُمرر محول، يستخدم التنفيذ المحلي الحالي عبر `createLocalStorageAdapter`.

هذا القرار لا يعني اختيار Supabase أو أي مزود مشترك. هو قرار عزل معماري فقط حتى لا ترتبط الواجهة أو نموذج المجال بمزود التخزين الانتقالي.

## عقد المحول

| العملية | المسؤولية |
|---|---|
| `load()` | إعادة snapshot كاملة أو `null` |
| `save(snapshot)` | حفظ snapshot وإعادة النسخة المحفوظة |
| `clear()` | حذف snapshot |
| `kind` | تعريف تنفيذي مثل `local` أو `memory` أو `shared` لاحقًا |

الـsnapshot الحالية تشمل الإصدار والعملاء والمشاريع والمهام والمخرجات والأعمال الداخلية وعمليات المزامنة والمسودات ووقت التحديث.

## التنفيذ الحالي

التنفيذ الفعلي هو `localStorage`. أُبقي هذا التنفيذ لأن القرار المشترك النهائي لم يعتمد بعد، ولأنه يحافظ على تجربة Pilot الفردية والاستعادة المحلية الحالية. أضيف تنفيذ ذاكرة للاختبارات والتحقق من أن المستودع لا يعتمد على `localStorage` مباشرة.

## ما يتيحه القرار

يمكن إضافة محول مشترك لاحقًا دون إعادة كتابة `mahdModel` أو مكونات الواجهة التي تستدعي المستودع. سيحتاج المحول المشترك في مرحلة لاحقة إلى هوية مستخدم ومساحة عمل، عزل tenant/workspace، عمليات قراءة وكتابة async، version أو ETag لمنع الكتابة فوق تغييرات عضو آخر، ومعالجة فشل الشبكة والتعارضات.

## ما لم يُقرر بعد

لم يُعتمد مزود التخزين المشترك، ولا شكل المصادقة، ولا نموذج workspace/team، ولا سياسة التزامن، ولا ما إذا كانت snapshot الكاملة ستبقى عقد النقل أو ستتحول العمليات إلى API لكل كيان. لذلك لا يجوز اعتبار `createMemoryStorageAdapter` تنفيذًا مشتركًا؛ هو اختبار عزل فقط.

## بوابة اعتماد المحول المشترك

لا يُوصل محول بعيد قبل اعتماد: هوية مساحة العمل، العضويات والصلاحيات، versioning/concurrency، schema migration، سياسة offline/retry، وحماية البيانات. بعد اعتماد هذه القرارات يمكن بناء `shared` adapter يلتزم بالعقد نفسه أو تحديث العقد إلى واجهة async مع ترحيل المستهلكين باختبارات.
