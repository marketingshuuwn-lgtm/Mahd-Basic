# تقرير التحقق من بوابة توسيع مزامنة Trello

## الحكم التنفيذي

بوابة التوسع **غير مجتازة حاليًا** لأن Pilot الحقيقي لم يكتمل ببيانات تشغيل فعلية. بعد الفحص، تم اكتشاف فجوة مهمة: بوابة `mahdPilotGate` كانت موجودة ومختبرة، لكنها لم تكن مرتبطة بمسار تنفيذ Trello الفعلي. تم إغلاق هذه الفجوة؛ أصبح زر تنفيذ العملية المعتمدة يتحقق من وجود Pilot مكتمل قبل بناء خطة الكتابة أو استدعاء Trello.

## شرط Pilot قبل التوسع

لا يسمح المسار الآن بالتوسع إلا إذا وجد سجل Pilot مكتمل، وأحداث تشغيل مرتبطة به، ودقائق جهد أكبر من صفر، وحدث تسليم، وحدث قبول للتسليم. إذا فشل أي شرط، تتحول عملية المزامنة إلى `failed` محليًا مع سبب واضح، ولا يصل التنفيذ إلى Trello.

هذا الحارس لا يثبت أن Pilot نجح؛ بل يمنع التوسع حتى يقدم Pilot بيانات فعلية ويجتاز الشروط.

## نطاق الكيانات المدعومة

| العملية | الحالة |
|---|---|
| `task.create` | مدعومة، وتتطلب قائمة Trello محددة وموافقة |
| `task.update` | مدعومة، وتتطلب `externalId` وموافقة |
| `client.create` | غير مدعومة، ولا توجد خريطة صريحة |
| `project.create` | غير مدعومة، ولا توجد خريطة صريحة |
| `deliverable.create` | غير مدعومة حاليًا |
| `internal_work.create` | غير مدعومة حاليًا |
| تحديث أو أرشفة كيانات غير المهمة | غير موسعة |

هذا النطاق يحافظ على عدم تخمين تمثيل العميل والمشروع والمخرج والعمل الداخلي داخل Trello.

## الكتابة المحروسة

خطة Trello تتطلب هدفًا صريحًا. إنشاء بطاقة يتطلب `listId`، وتحديث بطاقة يتطلب `externalId`. كلتا العمليتين تتطلبان موافقة محلية وحالة `approved` وهوية معتمد. بعد الفحص، يسبق هذه الشروط الآن فحص بوابة Pilot الفعلي.

إذا لم تتوفر بيانات الاتصال أو القائمة أو كانت العملية غير مدعومة، تفشل العملية محليًا دون كتابة خارجية.

## القراءة العكسية والتعارضات

القراءة العكسية متاحة للمهمة المرتبطة بمعرّف خارجي. يقارن الموصل الاسم والوصف والموعد والقائمة وحالة الإغلاق، ويحوّل اختلاف Trello إلى اقتراح تعارض يحتاج مراجعة. لا يتم تطبيق الفرق تلقائيًا.

المسار لا يوسع القراءة العكسية تلقائيًا إلى العميل أو المشروع أو المخرج أو العمل الداخلي؛ وهذا صحيح حاليًا لأن الخريطة الخارجية لهذه الكيانات لم تعتمد.

## الصلاحيات

التنفيذ محروس بصلاحية `execute_sync`، والـPilot الحالي يسمح للمالك المحلي فقط. هذه صلاحية Pilot تجريبية وليست نظام عضويات ومصادقة فعليًا، لذلك لا ينبغي اعتبارها حماية فريق نهائية.

## ما تم فحصه واختباره

تم فحص بوابة Pilot، وموصل Trello، وخطط الكتابة، والتعارضات، واختبارات الصلاحيات. بعد ربط البوابة بمسار التنفيذ، نجحت **39 اختبارًا دون فشل**، ونجح بناء الإنتاج و`git diff --check`.

## ما لم يحدث

لم يتم توسيع نطاق مزامنة Trello إلى كيانات جديدة. لم تُنفذ كتابة خارجية جديدة في هذه الجولة. لم يُعلن Pilot حقيقي ناجحًا، لأن سجل التشغيل الفعلي للعميل لم يكتمل بعد.

## القرار

حالة التوسع الحالية هي **محجوزة**. الترتيب الصحيح هو: تشغيل Pilot مستر آرت فعليًا، إدخال دقائق الجهد والأخطاء وإعادة العمل والتسليم والقبول، اجتياز البوابة، ثم اختيار توسع محدود يبدأ بالمهام المرتبطة فقط. بعد ذلك يمكن دراسة المخرج أو المشروع فقط بخريطة Trello صريحة ومراجعة منفصلة.
